# Mobile foundation (PLA-227)

This is a separately deployed Python API and native Android client. The Telegram,
CLI and Flet entry points are unchanged and have independent content channels.
This first increment checks connectivity; authentication, download queues and local
playback are added by subsequent cards. It is not the complete MVP.

## Run API

```bash
python3 -m venv .venv-server
.venv-server/bin/pip install -r backend/requirements-dev.txt
TUBEGO_DATA_DIR=./data PYTHONPATH=backend .venv-server/bin/uvicorn tubego_server.main:app
.venv-server/bin/pytest -q backend/tests
```

Python 3.12 is used in Docker/CI. `TUBEGO_DATA_DIR` is resolved to an absolute path
and holds `tubego.sqlite3`. Mount the entire directory (including SQLite WAL files)
on persistent local disk. Schema migrations run on startup in an immediate
transaction; foreign keys are enabled on every connection. Writes use
`app.state.db.transaction()` and reads must close `app.state.db.connect()` with
`contextlib.closing`. New migrations must increment `SCHEMA_VERSION` and handle
all prior versions without discarding user data. Do not edit historical migrations.
SQLite storage is for one deployment, not a shared network filesystem.

`docker compose -f compose.mobile.yaml up --build -d` starts the server bound to
localhost port 8000. Provision a trusted HTTPS reverse proxy separately: the app
rejects HTTP, URLs with credentials, paths, queries and fragments. Production must
not expose maintenance/resource endpoints until their authentication is implemented.
The health and version endpoints are intentionally public and reveal no user data.
The container runs as non-root and includes ffmpeg for subsequent download work.

## API v1 contract

- `GET /api/v1/health`: `{ "status": "ok", "version": "0.1.0", "database": "ok" }`;
  checks database connectivity. A database exception is a server error, not a false success.
- `GET /api/v1/version`: `{ "version": "0.1.0", "api_version": "v1" }`.
- `GET /api/v1/openapi.json`: machine-readable API contract.
- `GET /api/v1/docs`: interactive contract reference.

Future routers live in `backend/tubego_server/routers/` by responsibility.
`create_app(Settings(...))` supports isolated storage in tests. IDs are opaque TEXT
(UUIDs generated by feature code); timestamps are UTC ISO-8601 strings. Never trust
client ownership IDs: future authentication must derive user ID from sessions.

## Initial schema (user_version=1)

Exact SQL is in `backend/tubego_server/db.py`. Columns:

| Table | Columns |
| --- | --- |
| users | id, email (case-insensitive unique), password_hash, role, status, email_verified_at, created_at, updated_at |
| devices | id, user_id, name, platform, last_seen_at, revoked_at, created_at |
| sessions | id, user_id, device_id, token_hash (unique), expires_at, revoked_at, created_at |
| resources | id, user_id, source_url, source_key, title, duration_seconds, media_format, quality, server_path, size_bytes, ready_at, first_delivered_at, server_deleted_at, created_at, updated_at |
| tasks | id, user_id, resource_id, status, priority, progress, attempts, error_code, error_message, created_at, updated_at |
| deliveries | resource_id + device_id (composite key), status, downloaded_bytes, confirmed_at, deleted_at, updated_at |
| settings | scope + owner_id + key (composite key), value_json, updated_at |
| audit | id (integer sequence), actor_user_id, action, target_id, detail_json, created_at |
| commands | id, user_id, device_id, kind, payload_json, status, result_json, created_at, updated_at |
| events | id (integer sequence), user_id, device_id, kind, payload_json, created_at |

This schema reserves relationships; endpoints and semantics are delivered per card.
User-owned content is isolated from Telegram. A resource record represents permanent
history and must survive media file removal. Settings scope names: `global`, `user`,
`device`; JSON encoding is performed by the feature that owns a key. Audit is retained
independently of deleted user rows. API tokens will store only their hashes.

## Android

`android/` is an Android Java app (`dev.arglabs.tubego`), minSdk 29, target/compileSdk
35, AGP 8.9.3, Gradle 8.11.1, JDK 21 build runtime / Java 17 source. With Gradle
8.11.1 and Android SDK installed:

```bash
gradle -p android assembleDebug lintDebug testDebugUnitTest
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

CI installs the matching toolchain and uploads the debug APK. No release signing
keys are in the repository. The initial screen stores the HTTPS server origin in
private preferences and checks health off the UI thread, with network timeouts,
redirect refusal and bounded response size. Backup and cleartext networking are
explicitly disabled. No users, tokens, downloads or permissions other than INTERNET
exist in this increment. `ApiClient` is the transport seam for future feature work.
